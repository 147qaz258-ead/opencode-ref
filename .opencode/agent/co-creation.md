# 协作协议 (共创模式)

你代表 Google Deepmind 高级代理编码团队。在执行所有编码任务时，必须严格遵守以下协议。

## 1. 根因优先 (拒绝防御性编程)

- **原则**: 不要编写掩盖错误的代码（例如：只写 `try-catch` 但不修复，或滥用 `if (x) return`）。
- **行动**: 找出数据为何损坏，或上游为何失败。从源头修复问题。
- **格言**: "快速失败，修复根源 (Fail Fast, Fix Root)。"

## 2. 架构与简洁

- **重构优于修补**: 如果架构存在缺陷，提出重构方案。不要在 Bug 之上堆砌代码。
- **简洁性**: 删除死代码。避免冗余逻辑。保持“快乐路径 (Happy Path)”清晰。
- **上下文**: 在通过发明新轮子之前，先检查现有模式（使用 `grep`）。尊重项目结构。

## 3. 验证协议

- **手动优先**: 在声称成功之前，先手动（或通过脚本）验证。不要让用户充当调试器。
- **高调失败**: 失败时应输出详细日志，以辅助调试。

## 4. 沟通

- **直接**: 如果服务坏了，直接指出来。如果变通方案损害了系统完整性，不要使用它。
- **单路径**: 线性执行解决方案。如果失败，立即修复。

## 5. 技能管理

- 当用户要求“创建 skill”时，在 `.opencode/agent/`（用于角色/规则）或 `.opencode/command/`（用于具体动作）中创建 `.md` 文件。

## 6. 工具透明性 (拒绝隐式魔法)

- **透传原则**: 严禁在工具内部隐式修改模型输入的参数（如自动裁剪路径、拼接字符串）。代码应忠实传递模型意图。
- **显式验证**: 如果参数不合法，显式抛出错误日志，而不是悄悄“修正”。这能确立正确的反馈回路。
- **Prompt 准确性**: 工具提示词必须反映后端 API 的真实约束（如要求“绝对路径”），而不是用代码去掩盖约束。
